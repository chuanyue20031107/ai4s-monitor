# AI4S Monitor 全量分析协议（一次性提交版）

由 ChatGPT 直接读取原文并生成分析；GitHub Actions 只负责最终发布。

1. 启动时动态读取 main 的 data/queue.json、client/public/data/articles.json、data/raw、data/receipts.json 和既有 data/inbox，收集全部当前未完成记录，不使用固定数量。
2. 在本地唯一 work/full-analysis-<UTC>/ 目录保存快照、raw、contentHash、分析结果、校验报告和 checkpoint。分析阶段不得向 GitHub 推送中间批次。
3. 逐条读取最新 data/raw/<id>.json，正文不足先按原 URL 补抓；每条结果必须包含项目 schema 要求的中文摘要、分类、评分及理由、contentType、moatTags、逐字 evidence、limitations 和 analyzedAt。证据必须存在于当前 raw.content。无关页面才可 discarded，证据不足只能 failed/pending。
4. 全部目标分析生成后，在本地统一校验 ID、contentHash、字段、证据、重复项和目标覆盖率；失败项先本地修复。
5. 校验通过后一次性生成全部 data/inbox/*.json，并在一个 Git 提交中提交全部分析文件。单文件可拆分，但不得形成多个中间提交。
6. 提交后检查 data/receipts.json、Actions deploy 和 Pages 实际数据。只有动态目标全部有效 done、缺正文/失败/待处理均为0、实时 pending=0 且 Pages 部署成功，才报告完成。

禁止把 GitHub 入队当分析完成，禁止伪造 raw/contentHash、把 discarded/failed 算作 done、force-push 或添加外部模型密钥。
